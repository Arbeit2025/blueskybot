# 設計メモ

## 目的

Bluesky アカウントへ、本人の手動投稿とは別に、決まった内容を
1日8回自動投稿する。対象は投稿のみ。内訳は挨拶3回（08:00
おはよう／12:00 こんにちは／19:00 こんばんは）、自作ミニゲーム集の
宣伝2回（10:00／16:00、URL付き）、ゲーム案募集3回（09:00／20:00／
01:00、URL付き）で、時刻は全て JST。

## 構成

- `bot/template.py` — 純粋ロジック。テンプレート展開（日付・曜日）、
  文字数検証（上限300。len() はコードポイント数で書記素数以上に
  なるため安全側の判定）、リンク用 facets の生成（UTF-8バイト位置）。
- `bot/state.py` — スロット単位の同日二重投稿ガード（JSONファイル、
  キーは `日付:スロットID`）。GitHub Actions はファイルシステムが
  揮発するため、これは補助的な防御。本命の防御は「各スロットの
  スケジュールは1日1回」。
- `bot/bsky_client.py` — AT Protocol の最小クライアント（標準
  ライブラリのみ、依存なし）。createSession でログインし、
  com.atproto.repo.createRecord で app.bsky.feed.post を作る。
  レコード生成は純粋関数 build_post_record に分離。
- `bot/post_daily.py` — CLI。dry-run 既定（無指定なら全スロットの
  文面を表示）。実投稿は `--post` ＋ `--slot` ＋ `POST_ENABLED=true`
  ＋ 認証情報2点が揃った時だけ。
- `config/post.json` — スロット定義（`id`／`time_jst`／`template`）。
  同じ種別のスロットは `{slot_time}` で本文が少しずつ変わる。
- `.github/workflows/daily-post.yml` — cron 8本（UTC）。発火した
  cron 文字列からスロットを特定する。手動実行時はスロットと
  dry-run を選べる。`POST_ENABLED` 変数がキルスイッチ。

## なぜ日付を入れるのか

Bluesky は X のような重複投稿の拒否はしないが、完全に同一の文面を
毎日流すのは読み手にも運用上も好ましくない。「定型」の核は保ち、
日付・曜日で毎日ユニークにする。

## X 版との違い

- 課金なし（X は投稿ごと従量課金、URL付きは割高）。
- 認証は OAuth 1.0a の4点セットではなく、ハンドル＋アプリ
  パスワードの2点。アプリパスワードは単独で失効できる。
- 文字数上限は300（X の重み付き280ではない）。
- URL は facets を付けないとリンクにならない（X との大きな違い）。

## リスクと対策

- アカウントへの影響： Bot の不具合はそのまま投稿として出る。
  → 文面は設定ファイル固定、生成 AI で文を作らない。上限は1日1件。
- 認証情報の漏洩： → アプリパスワード＋Secrets / .env のみ。
  本体パスワードは使わない。コードと文書に実値を書かない。
- レート制限： 書き込みは 5,000 ポイント/時・35,000/日（作成=3）。
  1日8件でも24ポイントで、到達し得ない。
- 投稿頻度： 宣伝・募集が1日5件と多めなので、文頭表記で自動投稿で
  あることを明示し、止めたくなったら `POST_ENABLED` で即停止できる
  ようにしてある。反応を見て頻度を落とす場合は、ワークフローの
  cron とスロット定義を削るだけでよい。
